# 文件日期提取（Quicker 动作）

版本：0.02

一个基于 Quicker「运行C#代码」模块的组合动作。传入单个文件路径或路径列表，按固定顺序尝试获取日期，并根据输入格式自适应输出单个值或列表。

## 功能

- 输入支持单个文本路径、多行文本路径列表，以及 Quicker 列表变量。
- 先判断路径是否为文件。文件夹、无效路径、不存在的路径直接跳过，不产生对应输出。
- 按以下顺序匹配，任意一项成功即停止：
  1. 文件名中的日期（可开关）
  2. EXIF 拍摄日期（可开关）
  3. 文件修改日期（可开关）
  4. 文件创建日期（可开关）
- 单个输入时输出单个值；列表输入时输出列表。

## 输入参数

| 变量名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 输入文件路径 | 文本 | 空 | 单个路径，或多行路径（每行一个）。如果直接传入 Quicker 列表变量，脚本也会按列表处理 |
| 最早起始年份 | 整数 | 1900 | 仅用于文件名日期。有效年份范围为该值到当前年 |
| 匹配文件名日期 | 布尔 | true | 是否尝试从文件名提取日期 |
| 匹配exif拍摄日期 | 布尔 | true | 是否尝试读取 EXIF 拍摄日期 |
| 匹配修改日期 | 布尔 | true | 是否使用文件修改日期 |
| 匹配创建日期 | 布尔 | true | 是否使用文件创建日期 |

## 输出参数

输出变量使用动态对象类型，因为同一个变量需要在单个输入时保存单值，在列表输入时保存文本列表。

| 变量名 | 单个输入 | 列表输入 |
|--------|----------|----------|
| date | 日期时间（DateTime） | 日期文本列表，元素格式`yyyy-MM-dd HH:mm:ss` |
| yyyy | 文本，四位年份 | 文本列表 |
| mm | 文本，两位月份，如`02` | 文本列表 |
| dd | 文本，两位日期，如`02` | 文本列表 |
| yyyy_MM | 文本，格式`yyyy.MM`，如`2020.02` | 文本列表 |

Quicker 变量名不允许包含点号，因此`yyyy.mm`格式的变量名使用`yyyy_MM`，值仍为`yyyy.MM`格式。

### 输入格式与输出格式的对应关系

- 单个文本路径（不含换行，或只有一个非空行）：按单个模式处理，输出单值。
- 多行文本（两个及以上非空行）：按列表模式处理，每行一个路径，输出列表。
- Quicker 列表变量（`List<string>`等可枚举类型）：按列表模式处理，输出列表。
- 列表模式即使只有一项，也输出列表，不折叠为单值。

## 日期匹配规则

### 1. 文件名日期

只检查主文件名，不检查目录名，也不检查扩展名。按以下格式依次尝试：

- 格式1：`yyyy-mm-dd`，例如`2020-02-02`
- 格式2：`yyyymmdd`，例如`20200202`

约束：

- 年份必须在「最早起始年份」到当前年之间。
- 日期必须是真实存在的日期，`2020-13-01`、`2020-02-30`会被忽略。
- 日期前必须是字符串起始或非数字字符。`x2020-02-02y`可以匹配，`120200202`不会从中间截取。
- 格式1优先于格式2。同一格式有多个候选时，取第一个合法候选。
- 月份和日期必须为两位，`2020-2-2`不匹配。

### 2. EXIF 拍摄日期

- 支持 JPEG（APP1/Exif 段）与 TIFF 结构文件，大小端均支持。
- 优先读取`DateTimeOriginal`（0x9003）；不存在时读取`DateTimeDigitized`（0x9004）。
- EXIF 日期格式按`yyyy:MM:dd HH:mm:ss`等标准形式解析。
- 文件大于256MB时跳过 EXIF 读取，避免一次读入过多数据。
- 读取失败、格式损坏或没有拍摄日期时，视为不匹配并继续下一来源。

### 3. 修改日期

使用`File.GetLastWriteTime`，即 Windows 资源管理器中看到的“修改日期”。

### 4. 创建日期

使用`File.GetCreationTime`，即 Windows 资源管理器中看到的“创建日期”。

修改日期和创建日期不受「最早起始年份」限制。

## 跳过与失败处理

- 文件夹、无效路径、不存在的路径：跳过，不输出对应项。
- 单个输入且文件存在，但所有启用的来源都没有日期：抛出异常，C# 步骤返回失败。
- 列表输入中某个文件没有日期：跳过该项，继续处理其余文件，不中断整个列表。
- 列表输入全部无效或全部没有日期：输出空列表。

## 安装与使用

### 方式一：导入动作 JSON

1. 打开 Quicker 面板。
2. 在空白处右键，选择导入动作，选择`dist/FileDateExtractor.quicker.json`。
3. 运行动作，在表单中填写文件路径和开关，点击确定。路径框支持多行，每行一个路径。
4. 结果写入动作变量`date`、`yyyy`、`mm`、`dd`、`yyyy_MM`，供后续步骤使用。

### 方式二：手动创建

1. 新建组合动作，按上表创建6个输入变量和5个输出变量（变量名必须一致），再创建`formOk`、`scriptOk`两个布尔变量用于步骤状态。输出变量类型选择“对象”。
2. 添加「多字段表单」步骤，将6个输入变量加入表单；`输入文件路径`使用多行文本框。
3. 添加「运行C#代码」步骤：
   - 运行模式：普通模式（Roslyn）
   - 脚本内容：粘贴`src/FileDateExtractor.cs`
   - 执行线程：后台线程（MTA）
   - 开启磁盘缓存：是
4. 如需在批量循环中使用，可关闭 C# 步骤的「失败后停止」，由后续步骤判断`isSuccess`。

## 构建与测试

生成动作 JSON：

```bash
python3 tools/build_action.py
```

运行回归测试（需要`mono-mcs`与`mono`）：

```bash
./tests/run_tests.sh
```

测试覆盖32个用例，包括两种文件名格式、前置数字边界、年份范围、非法日期、大小端EXIF、EXIF缺失时的回退、修改/创建日期、文件夹跳过、缺失文件跳过、单个与列表模式、多行文本、单元素列表、空列表、列表中的无效项跳过等。

## 已知限制

- 文件名日期只识别两位月份和日期，不识别`2020-2-2`。
- 文件名日期只检查日期前边界，不检查后边界。
- 不解析 HEIC 等非 JPEG/TIFF 容器的 EXIF。
- EXIF 只读取拍摄日期与数字化日期，不把 EXIF 的`DateTime`（0x0132）当作拍摄日期。
- 文件修改日期和创建日期使用系统本地时间。
- 列表输入时，输出列表只包含成功提取日期的文件，长度可能小于输入列表。
- 输出变量为动态对象，后续步骤需要按实际类型访问：单个模式是`DateTime`/`string`，列表模式是`List<string>`。
